## Decisions to resolve

- **Responsibility and source of truth.** Where should product state, domain rules, persistence and side effects be owned and coordinated? Identify competing ownership, hidden lifecycle assumptions and dependencies that make a change difficult to reason about.
- **Sharing and isolation.** Which capabilities belong to one feature, which have an app/shared-domain responsibility, and which are system concerns? Assess whether existing composition and dependency directions support independent changes. Justify extraction or consolidation through actual responsibility and change needs.
- **Behavioral contracts.** Which observable behaviors and compatibility obligations must survive a reorganization? Establish their owners and appropriate evidence through the matrix. Reassess tests and guidance that freeze incidental structure or duplicate another owner's guarantee.

## Outcome and evidence

Implement the selected boundaries and expose the contracts needed across them. Keep product semantics and enduring decisions at their owners. Explain consequential changes through representative change scenarios, alternatives and maintenance effects; avoid a second feature inventory in this plan.

Validate preserved behavior and compatibility, and demonstrate that representative feature work reaches the appropriate owners without unnecessary cross-area changes. Use task evaluations to assess discovery and decision quality alongside behavioral and dependency evidence. Revisit system or tooling choices when product findings expose a gap.

Completion requires a justified app/feature architecture, implemented changes, demonstrated product guarantees and clearly owned residual judgments. Obtain user acceptance of the integrated rearchitecture baseline before Phase 04.

### Selected boundaries and alternatives

The existing direction is sound: app entrypoints and root routes own startup, routing, global styles and route fallback; thin file routes select feature views; the timer owns its data, commands and product copy; shared UI owns brand, semantics, focus primitives and material/motion contracts. Source/import/CSS inspection found no reverse feature dependency in shared components. Feature styling uses the documented Dial, Switch and Button root custom properties, semantic theme tokens and caller-owned classes. Existing import lint remains a partial static safeguard, not proof about arbitrary dynamic, transitive or CSS dependencies.

Keep `TimerLayout` as the nearest coordinating owner. Its single `{config, session}` spans editor and playback; context distributes that state and commands rather than storing another copy. URLs choose the view, while session mode chooses playback/finish/save state. The wall clock is authoritative; intervals and visibility events only refresh it. Pure phase/timeline calculations derive from config. Audio is lazy, belongs to the layout lifetime, never gates timer commands, and invalidates obsolete playback/error results on stop or disposal. Tab restoration deliberately skips cues missed while the document was closed. Automatic completion, explicit Finish and explicit Save retain their existing meanings.

Consolidated browser I/O into `timer-storage.ts`; `timer-state.ts` retains pure configuration validation/migration and domain calculations. Removed `timer-draft.ts` and updated all callers. Existing storage keys and unversioned payloads remain compatible; reads do not rewrite preferences, invalid/denied reads fall back, failed explicit saves retain the draft for retry, and failed tab writes leave the in-memory timer usable. Restored sessions now retain only validated canonical fields. Downgrade preservation of unknown future fields is not promised. These contracts live in source JSDoc and the contributor README.

A global store, generic repository/persistence framework, blanket reducer/controller split and directory renaming would add owners without another consumer or demonstrated transition need. Choicebox/Timeline promotion also lacks a second independent consumer: current tone selection, chime markers, labels and commands are timer responsibilities, composed from the existing neutral controls/disclosure. Reconsider shared-domain extraction when real features can name rules that must change together; another feature can currently add its routes and state without reaching the timer context or shared UI internals.
