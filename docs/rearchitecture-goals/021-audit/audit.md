# Independent guidance audit — November 7, 2026

**Status: audit and authorized integration complete.** The active matrix, installed skills, README/AGENTS routing and convention ownership now form one workflow. The user installed the four skills and applied the callback-lint change; integration aligned their guidance and closed the ownership mapping. The 67 recorded implementations describe the original frozen baseline, not the later integration. No new tests or evaluations were run during integration. Technical inventories, results and tools remain local evidence; see the [evidence locations](../021-tooling.md#evidence-retention).

The principal finding is that Phase 02's no-restoration inference was unsupported. This audit provides actual implementation evidence, but it does **not** establish that skills are unnecessary: the baseline already contains substantial semantic guidance, and these bounded tasks mostly reach a quality ceiling in every condition. Integration uses the evidence and explicit owner decisions; additional experiments are optional ways to resolve specific future questions.

## Why Phase 02's inference is reopened

Phase 02 established useful static/runtime checks and contributor routing. Its two read-only before/after exercises compared existing guidance with README changes, not credible restored skills, and did not execute the harder state/composition implementations. They cannot establish that no skills should return. The new audit asks separately whether guidance content helps, whether skill discovery helps, and which guarantees still need verification and human ownership.

The [matrix design in the 021 plan](../021-tooling.md#matrix-design) is implemented in the [active quality policy](../../../.agents/skills/design-system-maintainer/references/quality-ownership.md), treating those responsibilities as complementary and human review/repair as costs. The [historical inventory](../../../.audit-evidence/021/audit/historical-inventory.md) covers all 37 files, 120 headings and the UI entrypoint's unheaded workflow. The [104-concern register](../../../.audit-evidence/021/audit/historical-rule-register.md) preserves the original assessment: 34 concerns have partial related-task evidence and 70 have no directly mapped implementation comparison. The [integration mapping](../../../.audit-evidence/021/integration/ownership-decisions.json) adds current owners without changing those historical outcomes. A package-level task result is not isolated proof of a rule's efficacy.

The independent inventory was checked against the actual source and installed APIs. That review corrected two overly broad classifications: React Activity/resource hints and client Intl formatting remain applicable conditional techniques; only their server/hydration-specific portions are inapplicable to this client app. Product-specific timer details remain with their feature rather than becoming universal UI instructions.

## Experimental design and scope

The frozen baseline contains 170 files from the complete working tree, including the staged Phase 03 architecture. HEAD alone would have omitted that work. Its full `bun run verify` passed **270 tests in 31 files**, build, types, lint and color policy; the test runner reported 22.82 seconds. Initial restricted local-server failure is retained as setup evidence, not a code failure.

Four candidates were evaluated as inactive drafts and have since been installed by the user: [React lifetime](../../../.agents/skills/react-lifetime/SKILL.md), [React composition](../../../.agents/skills/react-composition/SKILL.md), [interaction evidence](../../../.agents/skills/interaction-evidence/SKILL.md), and [visual design](../../../.agents/skills/visual-design/SKILL.md). Their evaluated versions contain 459, 478, 311 and 338 words including metadata respectively. The [021 handoff provenance](../021-tooling.md#skill-provenance) records historical sources and attribution. Visual design and composition remain independently discoverable.

The [protocol](../../../.audit-evidence/021/audit/evals/protocol.md), task prompts, rubrics and hidden tests were prepared before candidate results were available. Separate fixture authors did not use candidate drafts. Reference implementations pass; two plausible bad variants per task fail runtime assertions. Sources use `.fixture` suffixes and cannot enter normal app execution. Reference implementations are calibration tools, not the only acceptable architecture.

Priority development trials compare the current baseline, the same substantive guidance in a linked document, and that content as a normally discovered skill: two tasks per family, three fresh repetitions per condition. Every run uses GPT-6.1 Sol Medium with delegation disabled, produces a real patch and retains commands, usage, repairs and first-final artifacts. Withheld tests run only after completion. Source review uses anonymous packets and a predefined rubric, with an independent agent review and final orchestrator judgment. This is agent review, not measured human review.

The [acceptance interpretation notes](../../../.audit-evidence/021/audit/evals/interpretation-notes.md) prevent undeclared DOM-shape assumptions from rejecting semantically valid compositions. Any semantic adjudication must preserve the original result and operate on unchanged agent output.

## Setup findings and evidence boundaries

The CLI initially rejected an incompatible option pair before any model calls. A subsequent three-run pilot exposed shared dependency-cache permission failures and unrelated full-suite timing failures during simultaneous verification. Those pilots remain separate from the confirmatory comparison. The final runner uses independently writable dependency copies, frozen-input validation, process-group timeout cleanup and serialized evaluator checks. Ten no-model runner regressions pass.

Some unchanged timer/scroll/transition tests still fail intermittently during concurrent trial work. Their cause is not established by this audit. Logs and retry costs are retained; passing isolated task tests do not erase failed full verification, and these unrelated failures cannot be attributed to a skill intervention without evidence. The original source bytes are checked separately from the trial additions.

Focused follow-up on the unchanged baseline passed the timer-screen suite (21.87 s) and the affected navigation/product-composition/summary browser suites (3.80 s). This establishes that the observed failures are not consistently reproducible in those focused runs; it does not prove their cause or make the full workflow uniformly reliable.

A concrete policy conflict was reproduced with the ordinary lint command in a disposable copy. Both an inline native-button handler and an ordinary local handler fail `performance/noJsxPropsBind`; wrapping the same handler in `useCallback` passes. [Exact sources and diagnostics](../../../.audit-evidence/021/audit/evals/policy-probe-results.json) record exits and timings. The README instead says performance recipes need measured workloads and should avoid blanket memoization. Trial implementations consequently add callback wrappers or suppression comments. **Recommendation:** turn off this blanket rule and keep callback identity requirements with the affected contract or measured performance case. The user has since applied that change in [biome.json](../../../biome.json). In an isolated [proposal probe](../../../.audit-evidence/021/audit/evals/policy-proposal-results.json), all three valid handler styles pass while an actual missing Effect dependency still fails and its complete counterpart passes. A compensating skill is not the default remedy for a prescriptive lint policy; no runtime speed difference is claimed.

At trial time, all four inactive drafts passed the repository's maintained Intent metadata validator. The skill-creator Python helper could not run because this host lacks PyYAML; its additional naming/length/unfinished-scaffold conditions were inspected directly. No dependency was installed to duplicate the existing structural check. Metadata validity is separate from implementation quality; the integration did not rerun validation commands.

The tasks are deliberately bounded and state desired behavior explicitly. Successful results do not establish guidance efficacy on larger, ambiguous changes, every historical rule or every future consumer. A ceiling result leaves the broader question inconclusive; it is not evidence that lint can choose architecture.

There are additional experimental limits. The external-store starter already imports its likely React primitive. The form/disclosure prompts explicitly require browser evidence, so they cannot establish independent environment selection by the interaction skill. Isolated copies omit Git metadata, and fixed fixture filenames conflict with the repository's ordinary naming rule; some failed commands therefore reflect laboratory setup or expected lint corrections. These affect absolute cost estimates and motivate more natural follow-up tasks. All conditions received the same starting fixtures. Reported command failures also include searches finding nothing; they are not a count of architectural mistakes.

The baseline includes the **active maintainer skill**, today's documentation, public contracts, tests and the model's existing ability. **There is no lint-only or skill-free condition.** Baseline success therefore cannot support a claim that scripts replace semantic guidance. It also uses the later Phase 03 source/documentation, so it cannot retroactively satisfy Phase 02's missing evaluations. The tested intervention adds focused guidance; replacing broad documentation routing with a skill is a different cost hypothesis and would need its own controlled comparison.

The twelve full-verification failures concern unchanged timer, navigation, scroll/focus or lint-policy timing tests. Preserve both denominators; neither means that twelve implementations failed their task contract. Host load and repeated verification also affect elapsed cost, so this small comparison does not establish a stable latency advantage.

Normal discovery loaded every relevant skill body in the repeated trials. One documentation run saw the README link without opening the document. Source review found two noncritical public prop surfaces accepting children that their controls discard; the required caller layouts still work. These findings do not establish a repeated quality advantage for either additional candidate.

The transfer stage exposed another fixture assumption: empty mounted status regions are valid after cancellation. A [separate form acceptance variant](../../../.audit-evidence/021/audit/evals/adjudications/form-results.json) accepts an empty message while retaining cancellation, error, submission and validation assertions. Unlike the planner role interpretation, this correction was made after observing the first three form outputs. The original scores remain available; all conditions receive the same corrected test. Both semantic variants still pass their reference and reject both original bad examples.

A [post-hoc external-store diagnostic](../../../.audit-evidence/021/audit/evals/adjudications/store-receiver-results.json) tests a class-based store whose stable methods require their object receiver. The skill-guided output fails; baseline and documentation outputs pass. The public type does not prohibit that store, and the starter preserves its receiver. This is a concrete robustness gap beyond the frozen tests, not a repeated estimate of harm caused by the skill. It prevents treating the initial acceptance pass as universal correctness and needs an explicit future contract/example before a restoration recommendation.

Visual screening required two further grader corrections. The original hidden tests omitted the existing app stylesheet and sampled only real-element geometry/opacity; valid color and pseudo-element cues were therefore missed. [App-context results](../../../.audit-evidence/021/audit/evals/adjudications/visual-environment-results.json) and [appearance-sampling results](../../../.audit-evidence/021/audit/evals/adjudications/motion-appearance-results.json) apply the same corrections to every unchanged output. Their references pass, the original invalid variants still fail, and an added no-summary-cue negative also fails. These were post-observation corrections. Together with the fieldset and empty-status cases, they show why future graders need several valid designs as well as bad variants. The original calibration comprised 53 reference test cases and 22 bad variants across 11 tasks; rerunning them does not create more independent cases.

Direct [rendered review](../../../.audit-evidence/021/audit/evals/results/visual-review.json) covered all six visual outputs, narrow/wide and long/text-resized content, keyboard focus, selection and reopening. The skill-guided content output retained a wider reading measure at 200% text; the baseline/documentation lists were more cramped. This single unblinded observation is a refinement candidate, not a replicated skill advantage. Motion color/underline cues were observed and settled. Reduced-motion browser assertions pass under the corrected environment, but no direct reduced-motion visual session was performed. Human brand acceptance, comfort, composited contrast and assistive-technology experience remain outstanding.

Normal discovery read the complete candidate in **20/20 relevant skill runs** and **19/20 documentation runs**. None of the four skill or four documentation negative conditions loaded the full candidate on the unrelated duration helper; all nine implementations, including the shared baseline, met acceptance. These are one distant negative task and mostly one-candidate catalogues. Nearby React negatives, overlapping candidate triggers and a combined catalogue remain untested. Explicit-invocation trials were unnecessary for diagnosing missing skill discovery here and were not run; they are not silently counted as normal discovery.

## Integrated decisions and evidence limits

The user authorized adoption and integration after reviewing the audit. These current decisions preserve the inconclusive efficacy findings; they are not claims that the new wording has been experimentally validated.

| Candidate | Decision from this audit | What would resolve it |
| --- | --- | --- |
| React lifetime | Installed; preserve method receivers and actual store identity as well as state/lifetime semantics. Incremental efficacy remains inconclusive. | A real affected service/store change needs receiver, replacement and adverse-ordering evidence; richer generalization remains optional future work. |
| React composition | Installed; explicit stateless molecule/state-owning organism taxonomy, current consumer plus independent usage example, and honest supported props/children. | Promotion and API tradeoffs remain reviewed against real callers; these small trials do not settle all abstractions. |
| Interaction evidence | Installed; guide evidence choice and accept valid semantic alternatives. Existing prompts prescribed browser evidence, limiting the efficacy claim. | Required interaction behavior, actual environment selection and remaining assistive-technology judgment. |
| Visual design | Installed independently of composition; use actual app styles and observe the cue allowed by the contract. | Human perception/brand acceptance and untested states; runtime samples do not certify comfort or contrast. |

No clause group was removed experimentally, so the original study does not establish a minimal retained rule set. Integration makes narrow corrections from observed failures and current repository ownership. Any future claim that revised wording improves generalization needs new unseen evidence; no such claim is made here, and another evaluation batch is not a prerequisite to the authorized integration.

The original audit recorded **27 source-owned concerns**, **two timer-specific contracts**, **four mechanically covered portions**, **64 inconclusive simplify/merge candidates** and **seven technology-specific examples inapplicable as written**. Those historical efficacy assessments remain intact. The integration mapping now assigns every concern to current guidance, verification and judgment owners; no concern is left ownerless pending a new experiment. Conditional client techniques remain eligible for a real workload. Applying the audit workflow does not itself establish a skill-maintenance skill's efficacy.

The [active matrix](../../../.agents/skills/design-system-maintainer/references/quality-ownership.md) implements the authorized design with explicit guidance, verification and judgment owners. No old/new matrix efficacy claim is made. The user-applied callback-lint change remains. The form/disclosure outputs were reviewed against the current promotion rule, with business actions and values retained by callers.

## Whole cost and next work

The 67 distinct implementations used **56,216,674 input tokens**, including **53,437,056 cached input**, and **442,475 output tokens**. Their summed agent elapsed time was **13,592.79 seconds**; evaluator execution added **1,908.69 seconds**, with **332.96 seconds** of evaluator queue wait. Trials overlapped, so those sums are not project wall time. The 1,142 commands included 276 nonzero exits, including expected no-match searches, fixture naming corrections and unchanged-suite failures. These are not 276 architectural errors. [Measured costs](../../../.audit-evidence/021/audit/evals/results/costs.json) and [excluded setup costs](../../../.audit-evidence/021/audit/evals/results/setup-costs.json) retain the units and denominators.

Authoring, inventory, orchestrator review, independent agent review, cloning and post-hoc adjudications add incompletely instrumented effort. Billed dollars and human review/repair/upkeep minutes are unknown. Human review still needs to settle visual/product acceptance and real promotion/API tradeoffs; that work is not treated as free.

The most useful cost hypothesis is now narrower routing. In development, 34/36 runs emitted the entire 5,122-word conventions document; all 36 emitted the 1,055-word README and 429-word maintainer skill. Eight also emitted the 1,370-word ownership matrix. Compare section-level documentation routing against a focused skill/reference workflow while preserving one authoritative contract owner and equal quality. The additive experiment here cannot demonstrate the savings of that replacement.

[Next experiments](next-experiments.md) specify those comparisons, nearby negatives, richer positive grader controls, human review measurement and family-specific residual work.
